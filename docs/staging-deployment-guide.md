# Staging环境部署与内部试用指南

## 1. 概述

本指南旨在指导如何在Staging(类生产)环境部署Amazon广告优化系统的新版本,并组织内部用户进行试用,收集反馈。

**目标:**
- 在真实数据环境下验证新功能的稳定性和业务价值
- 收集来自真实用户的反馈,发现潜在问题
- 为生产环境的灰度发布做最后准备

---

## 2. Staging环境部署

Staging环境应尽可能与生产环境保持一致,包括:
- **硬件配置:** 相同的服务器规格
- **网络环境:** 相同的网络拓扑和防火墙规则
- **数据库:** 生产数据库的只读副本或定期同步的克隆
- **域名:** 使用独立的子域名,如 `staging.your-app.com`

### 2.1. 部署流程

部署流程与测试环境类似,但需使用Staging环境的配置。

1. **拉取代码:** `git pull origin main`
2. **安装依赖:** `pnpm install`
3. **配置环境变量:** 编辑 `.env.staging` 文件,填入Staging环境的数据库和API凭证。
4. **数据库迁移:** `./scripts/run-migration.sh` (在生产数据库的克隆上执行)
5. **构建与启动:** `pnpm build && pnpm start`

### 2.2. 数据验证

部署完成后,需使用真实数据验证新功能的表现:

- **ML预算优化:** 检查预算分配建议是否符合业务逻辑。
- **智能洞察:** 验证AI建议是否具有实际指导意义。
- **组织管理:** 确保现有用户和组织数据迁移正确。

## 3. 内部试用

### 3.1. 试用用户

邀请5-10名内部用户参与试用,角色应覆盖:
- **广告投手:** 核心用户,关注日常操作和优化效果
- **运营经理:** 关注报表、策略和整体表现
- **产品经理:** 关注功能流程和用户体验
- **开发人员:** 关注系统性能和潜在bug

### 3.2. 试用任务

为试用用户提供一份任务清单,引导他们体验新功能:

- **任务1:** 使用ML预算优化功能,为你的一个核心广告活动重新分配预算。
- **任务2:** 查看智能洞察面板,找到一条"机会"类型的建议并尝试采纳。
- **任务3:** 创建一个符合你业务需求的自定义策略,并应用到至少2个广告活动。
- **任务4:** 邀请一位同事加入你的组织(如果适用)。
- **任务5:** 探索新功能,并尝试完成你日常工作中的一个优化任务。

### 3.3. 反馈收集

使用在线表单收集用户反馈,表单应包括以下内容:

**1. 总体评价 (1-5分)**
- 新功能易用性
- 新功能实用性
- 系统整体稳定性
- 系统响应速度

**2. 功能反馈**
- **最喜欢的新功能是哪个? 为什么?**
- **最不喜欢/最难用的新功能是哪个? 为什么?**
- **ML预算优化的建议是否合理?**
- **智能洞察的建议是否有帮助?**

**3. Bug报告**
- **问题描述:** (详细描述你遇到的问题)
- **复现步骤:** (如何让我们重现这个问题?)
- **页面URL:**
- **截图/录屏:** (可选,但强烈推荐)

**4. 开放性建议**
- **你认为新版本还有哪些可以改进的地方?**
- **你最期待的下一个功能是什么?**

### 3.4. 反馈处理

- **每日站会:** 每天同步收集到的反馈,快速响应严重问题。
- **Bug分类:** 将Bug按优先级(P0/P1/P2)分类,并分配给开发人员修复。
- **需求沉淀:** 将有价值的功能建议记录到产品需求池。

---

## 4. Staging阶段完成标准

- ✅ Staging环境稳定运行超过3天
- ✅ 无P0/P1级别的Bug
- ✅ 核心功能在真实数据下表现正常
- ✅ 收集到至少5份有效的用户反馈
- ✅ 所有反馈已评估和处理

满足以上条件后,即可进入**阶段4: 灰度发布**。
