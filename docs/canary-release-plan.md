# 灰度发布计划 (Canary Release)

## 1. 概述

本计划旨在通过灰度发布的方式,将Amazon广告优化系统的新版本逐步、安全地推向生产环境,最小化潜在风险,确保业务连续性。

**发布版本:** `main`分支最新版 (Commit: `a109ee1`)
**发布策略:** 基于用户百分比的金丝雀发布
**发布工具:** Nginx (或其他支持流量切分的网关)

---

## 2. 发布流程

### 2.1. 准备阶段 (Day 0)

1. **创建生产环境部署包:**
   ```bash
   # 拉取最新代码
   git pull origin main

   # 创建部署包
   pnpm build
   tar -czvf deployment.tar.gz build node_modules package.json .env.production
   ```

2. **部署新版本(金丝雀实例):**
   - 部署新版本到一台或多台独立的服务器(金丝雀实例)。
   - 新版本使用与生产环境相同的数据库和后端服务。
   - **注意:** 此时金丝雀实例不接收任何外部流量。

3. **配置流量切分:**
   - 在Nginx或网关中配置流量切分规则。
   - 初始状态下, **0%** 的流量被路由到金丝雀实例。

   **Nginx配置示例:**
   ```nginx
   upstream backend {
       server production-server-1.internal;
       server production-server-2.internal;
       # ...
   }

   upstream canary {
       server canary-server-1.internal;
   }

   split_clients "${remote_addr}${date_gmt}" $variant {
       0.0%    canary;
       *       backend;
   }

   server {
       # ...
       location / {
           proxy_pass http://$variant;
       }
   }
   ```

### 2.2. 灰度发布阶段

#### 第1天: 1% 流量

- **操作:** 将 `$variant` 的比例调整为 `1%`。
- **监控:**
  - **错误率:** 密切关注Sentry、CloudWatch等监控工具,新版本的错误率不应显著高于旧版本。
  - **性能指标:** 监控API响应时间、服务器CPU/内存使用率。
  - **业务指标:** 监控核心业务指标(如广告花费、销售额)是否正常。
- **持续时间:** 24小时

#### 第2天: 5% 流量

- **操作:** 将流量比例提升至 `5%`。
- **监控:** 继续监控所有指标,并开始关注用户反馈。
- **持续时间:** 24小时

#### 第3-4天: 20% 流量

- **操作:** 将流量比例提升至 `20%`。
- **监控:** 全面监控,并主动联系部分灰度用户收集反馈。
- **持续时间:** 48小时

#### 第5-6天: 50% 流量

- **操作:** 将流量比例提升至 `50%`。
- **监控:** 此时系统一半流量由新版本处理,需重点关注数据库和后端服务的负载。
- **持续时间:** 48小时

### 2.3. 全量发布阶段 (第7天)

- **操作:**
  1. 将流量比例提升至 `100%`。
  2. 运行24小时后,将旧版本服务器下线。
  3. 清理流量切分配置。
- **监控:** 继续监控1-2天,确保系统稳定。

## 3. 监控仪表盘

在灰度发布期间,必须建立一个统一的监控仪表盘(如Grafana、Datadog),实时对比新旧版本的核心指标。

### 3.1. 关键指标

| 指标分类 | 指标名称 | 阈值 |
| :--- | :--- | :--- |
| **系统** | API错误率 | < 0.5% |
| | P95响应时间 | < 800ms |
| | CPU使用率 | < 80% |
| **业务** | 广告同步成功率 | > 99.9% |
| | 优化建议生成量 | 与旧版持平 |
| | 用户活跃度 | 无明显下降 |

## 4. 回滚计划

如果在灰度发布过程中发现严重问题(如P0级Bug、系统崩溃、核心业务指标异常),应立即执行回滚。

### 4.1. 回滚步骤

1. **流量切回:** 立即将流量切分比例调整为 `0%`,所有流量将回到旧版本。
2. **问题排查:** 在隔离的金丝雀环境中排查问题。
3. **修复与验证:** 修复问题后,在金丝雀环境进行验证。
4. **重新发布:** 从 `1%` 流量重新开始灰度发布流程。

### 4.2. 触发回滚的条件

- 新版本错误率是旧版本的 **2倍** 以上。
- P95响应时间超过 **1500ms**。
- 核心业务指标下降超过 **10%**。
- 出现导致数据丢失或数据不一致的Bug。

---

## 5. 沟通计划

- **发布前:** 通知所有团队成员(开发、测试、运维、客服)发布计划。
- **发布中:** 在Slack/Teams等即时通讯工具中创建专门的发布频道,实时同步发布进度和监控情况。
- **发布后:** 发送发布总结邮件,宣布新版本成功上线。
