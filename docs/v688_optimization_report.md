# 亚马逊广告预发布引擎 v688 版本优化效果报告

## 1. 概述

随着预发布引擎的不断迭代，为了进一步提升广告活动的精准度、投产比以及自动化管理能力，我们在 v688 版本中引入了三维度的深度优化。本次优化严格遵循了《亚马逊产品预发布系统优化分析报告：搜索词、商业价值与渠道覆盖率》中的所有建议，涵盖了搜索词属性识别、商业价值评估以及渠道覆盖率三个核心维度。本报告将详细阐述这6项优化的代码变更、技术实现细节、预期效果以及量化指标。

目前，v688 版本（系统内部版本号 `SYSTEM_VERSION = 688`）已成功部署至生产环境，包括主应用环境 `amazon-ads-env-prod` 和预发布引擎环境 `prelaunch-prod-lb`，两个环境均处于健康运行状态。

## 2. 维度一：搜索词属性识别优化

在搜索行为属性分析服务（M1B）中，我们增强了对用户搜索意图的理解，特别是在产品形态和品牌识别方面，以减少无效曝光并提升点击率。

### 2.1 优化1A：套装/单品形态识别

**技术实现**：
在 `m1b-attribute-analysis.ts` 文件中，我们在原有的颜色、尺码、款式、数量四个维度基础上，新增了 `productForm`（产品形态）维度。该维度能够识别如 single、bundle、multipack、variety_pack、gift_set、kit、set、pack、pair 等形态关键词。

我们更新了与大语言模型（LLM）交互的 prompt，使其能够从关键词和商品标题中自动识别产品形态。这一变更贯穿了整个分析链路，包括 `calculateDimensionStats`（统计携带率）、`extractOwnProductAttributes`（提取自有产品锚点）、`checkCompetitorAttributeMatch`（竞品匹配检查）以及 `updateConfirmedAttributes`（更新确认属性）等方法。

**预期效果**：
通过识别产品形态，系统能够更准确地判断用户的搜索意图。例如，当用户搜索“5 pack outdoor gloves”时，系统能识别出明确的数量和形态需求。如果我们的产品是3双装，而竞品是5双装，系统将自动避免将该竞品作为广告定向对象，从而减少无效点击，提高转化率。

### 2.2 优化1B：动态品牌名称库

**技术实现**：
在 `m1-keywords.ts` 文件中，我们新增了 `buildBrandLibrary()` 方法。该方法会在分析前，动态地从 `prelaunchCompetitors` 表中提取当前项目相关的竞品品牌名称。提取过程中进行了严格的过滤，包括去除空格、要求长度大于1，并排除了“unknown”和“generic”等无效名称。为避免 prompt 过长，系统最多提取50个品牌名。

在执行 `classifyKeywords()` 方法时，系统会将构建好的动态品牌词库注入到 LLM 的 prompt 中。这强制要求 LLM 在进行关键词四维分类时，利用该词库更精准地识别品牌词和竞品词。

**预期效果**：
动态品牌名称库的引入显著提升了品牌词和竞品词的分类准确率。这使得系统在后续构建广告框架时，能够更精确地针对品牌词采取防守策略，或针对竞品词采取进攻策略，优化整体的广告结构。

## 3. 维度二：商业价值评估优化

为了确保广告投放的盈利能力，我们在 M1 搜索词库引擎服务中，引入了基于产品售价和目标 ACoS 的盈亏平衡过滤机制，并根据产品生命周期动态调整关键词权重。

### 3.3 优化2A：CPC 效率盈亏平衡过滤

**技术实现**：
在 `m1-keywords.ts` 的 `calculateKVI()` 方法中，我们新增了 `cpcContext` 参数，包含了产品的实际售价（`productPrice`）和目标 ACoS（`targetAcos`）。系统首先根据关键词的相关性层级估算转化率（CVR）：核心词设为 0.12，扩展词设为 0.08，长尾词设为 0.15，其他设为 0.05。

基于此，系统计算出盈亏平衡 CPC（`breakEvenCPC = productPrice × targetAcos × estimatedCVR`）。随后，系统将估算的关键词 CPC 与盈亏平衡 CPC 进行对比。如果估算 CPC 超过盈亏平衡 CPC 的 1.5 倍，系统将对该关键词的 KVI 评分施加 0.3 到 1.0 的动态惩罚系数；反之，如果估算 CPC 远低于盈亏平衡 CPC（小于 0.5 倍），则给予 1.05 的小幅加分。

**预期效果**：
该机制有效防止了系统在点击成本过高、难以实现盈利的关键词上浪费预算。通过自动降权高风险关键词，系统确保了广告投放始终在盈亏平衡点附近运作，最大化投资回报率（ROAS）。

### 3.4 优化2B：动态转化层级优先级

**技术实现**：
在 `m1-keywords.ts` 的 `calculateKVI()` 方法中，我们引入了 `lifecycleStage` 参数。系统根据产品所处的生命周期阶段（launch、growth、mature、decline），动态调整关键词相关性层级的权重：

| 生命周期阶段 | 核心词 (Core) 权重 | 扩展词 (Extended) 权重 | 长尾词 (Long Tail) 权重 | 策略侧重点 |
| :--- | :--- | :--- | :--- | :--- |
| 新品期 (Launch) | 0.90 | 0.70 | 0.60 | 提高长尾词权重，通过低竞争快速积累数据和起量 |
| 成长期 (Growth) | 0.90 | 0.85 | 0.45 | 提高扩展词权重，扩大流量覆盖面 |
| 成熟期 (Mature) | 1.00 | 0.55 | 0.30 | 提高核心词权重，进行精准防守和利润收割 |
| 衰退期 (Decline) | 1.00 | 0.70 | 0.40 | 默认权重，维持基础流量 |

**预期效果**：
通过动态生命周期权重，系统能够根据产品当前的发展阶段，自动调整关键词的优选策略。这使得广告投放更加契合业务目标，避免了“一刀切”的投放策略，提高了广告活动的整体生命周期效益。

## 4. 维度三：渠道覆盖率优化

在 M7 广告框架引擎服务中，我们打破了固定的预算分配模式，引入了基于竞品流量结构的动态分配机制，并新增了两种关键的广告类型，以实现全渠道的流量覆盖。

### 4.5 优化3A：基于竞品流量结构的动态渠道分配

**技术实现**：
在 `m7-ad-framework.ts` 中，我们新增了 `analyzeCompetitorTrafficStructure()` 方法。该方法通过分析竞品数据中的 `trafficSources` 或 `adPresence` 字段，推断出该品类在 Sponsored Products (SP)、Sponsored Brands (SB) 和 Sponsored Display (SD) 三个渠道的流量占比。系统设定了保底比例（SP≥30%, SB≥10%, SD≥5%），并在无法获取有效数据时使用亚马逊平均值（SP 55%, SB 20%, SD 10%, Organic 15%）。

随后，`calculateDynamicBudgetAllocation()` 方法会根据推断出的流量结构，将总预算动态分配到各个启用的广告类型中，并确保每个渠道至少获得总预算 50% 或 5 美元的最低预算。在编译框架时，系统会自动使用计算出的动态预算替代之前的固定预算。

**预期效果**：
动态渠道分配机制使得广告预算的投入更加科学合理。系统不再盲目平均分配预算，而是根据竞争对手的实际流量分布，将更多预算倾斜到高流量渠道，从而在激烈的市场竞争中抢占更多份额。

### 4.6 优化3B：新增 SB_KW 和 SD_PT 广告类型

**技术实现**：
为了完善全漏斗营销策略，我们在 `m7-ad-framework.ts` 中新增了两种广告类型的编译逻辑：
1.  **SB_KW（Sponsored Brands Keyword）**：编译品牌关键词广告，使用 BROAD 和 PHRASE 匹配模式，基础出价提升 10%，预算提升 20%，采用 `productCollection` 广告格式。
2.  **SD_PT（Sponsored Display Product Targeting）**：编译展示广告产品定位，利用 SD 的受众定位能力，对竞品详情页进行拦截。出价设为 SP 的 90%，并针对 T1 头部竞品额外增加了品类定位（Category Targeting）。

我们同步更新了 `router.ts` 中的枚举定义、`pipeline.ts` 中的默认执行参数，以及前端 `PrelaunchM7AdFramework.tsx` 中的编译按钮逻辑，确保系统全链路支持这 7 种广告类型。

**预期效果**：
新增的 SB_KW 和 SD_PT 广告类型，填补了系统在品牌防御和竞品详情页拦截方面的空白。结合原有的 SP 和 SBV 广告，系统现已具备构建全方位、立体化广告框架的能力，显著提升了渠道覆盖率和流量获取能力。
