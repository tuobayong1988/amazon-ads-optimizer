### 2.2. 上下文特征管道 (`contextualFeatureService.ts`)

该服务是整个系统的“眼睛”，负责从多维数据源中提取和计算**17维标准化特征向量**，为所有高级算法提供统一的上下文感知能力。其核心功能包括：

- **时间衰减加权**: 使用指数衰减函数（半衰期7天）计算近期绩效指标（如CVR、ROAS），赋予近期数据更高权重。
- **趋势特征**: 通过最小二乘法计算过去7天内关键指标（展现、点击、订单、花费）的趋势斜率，捕捉增长或下降的势头。
- **竞争环境特征**: 综合CPC波动率、CTR波动率和预估展示份额，量化竞争激烈程度。
- **时间上下文**: 包含星期几、小时、是否为节假日等时间特征。

所有特征最终通过 `featureVectorToArray` 函数归一化到 `[0, 1]` 区间，确保了不同量纲特征在模型中的权重一致性。

### 2.3. 强化学习数据记录器 (`rlDataRecorder.ts`)

为了实现离线强化学习（Offline RL），我们必须能够记录每一次出价决策的完整“足迹”。`rlDataRecorder` 负责在每次出价调整后，记录一个`State-Action-Reward` (SAR) 元组到 `rl_training_logs` 表中。

- **State**: 记录决策前的完整上下文特征向量和当前出价。
- **Action**: 记录调整前后的出价（`bidBefore`, `bidAfter`）。
- **Reward**: 初始为空，通过一个后台的`backfillRewards`定时任务，在7-14天后计算并回填该次出价调整带来的**增量利润**作为奖励。

这种延迟奖励回填机制是RL在广告优化中应用的关键，它确保了奖励的计算能够覆盖用户的完整转化周期。

## 3. P1: 核心模型层 (Core Models)

P1层是系统的“大脑”，包含了三个核心的预测与决策模型，它们共同构成了智能出价的基础。

### 3.1. Sigmoid曲线拟合 (`sigmoidCurveFitter.ts`)

该模块替代了原有的简单对数模型，使用更精确的**四参数Sigmoid函数**来拟合“出价-展现量”关系曲线。这使得我们能够更准确地预测在不同出价水平下的市场反应。

> **Sigmoid函数**: `Impressions(bid) = L / (1 + exp(-k * (bid - x0))) + b`

- **核心算法**: 我们实现了**Levenberg-Marquardt (LM)算法**，这是一个高效的非线性最小二乘优化算法，用于从历史数据中拟合出最优的 `L, k, x0, b` 四个参数。
- **利润最大化**: 基于拟合出的曲线，我们通过求解利润函数 `Profit(bid) = Impressions(bid) * CTR * (AOV * CVR - CPC(bid))` 的导数为零的点，来计算**理论上的最优出价**。我们使用黄金分割法进行高效的数值寻优。
- **验证结果**: 在验证脚本中，我们证明了该模块能够从带噪声的数据中精确恢复出真实的Sigmoid参数（R² > 0.99），并找到正确的利润最大化出价点。

### 3.2. 上下文赌博机 (`contextualBanditService.ts`)

为了在数据不足、无法精确拟合Sigmoid曲线时也能做出智能决策，我们引入了**LinUCB (Linear Upper Confidence Bound) 上下文赌博机**算法。它将出价决策建模为一个“探索-利用”问题。

- **“臂” (Arm)**: 我们定义了五种出价策略作为“臂”：激进加价、温和加价、保守微调、温和降价、明显降价。
- **上下文 (Context)**: 使用`contextualFeatureService`提供的17维特征向量作为上下文。
- **决策逻辑**: LinUCB的核心是为每个臂计算一个UCB分数，该分数是“预期回报”（利用）和“不确定性”（探索）的和。

> **LinUCB公式**: `UCB(a) = θ_a^T * x + α * sqrt(x^T * A_a^{-1} * x)`

算法会选择UCB分数最高的臂，并根据分数在臂的出价倍率范围内进行插值，从而实现动态、平滑的出价调整。这使得系统能够在不断变化的市场中自动学习最优的出价策略。

### 3.3. 因果推断引擎 (`causalInferenceEngine.ts`)

广告优化的核心是评估“如果我不做这个出价调整，结果会怎样？”。为了回答这个问题，我们引入了因果推断，具体实现了**Difference-in-Differences (DID)**算法。

- **核心思想**: DID通过比较“处理组”（出价被调整的关键词）和“对照组”（出价未调整的相似关键词）在调整前后的绩效变化差异，来剔除市场整体趋势（如节假日）等混淆因素，从而分离出出价调整本身带来的**真实因果效应 (ITE - Individual Treatment Effect)**。

> **DID公式**: `ITE = (Y_treat_after - Y_treat_before) - (Y_control_after - Y_control_before)`

- **对照组构建**: 我们通过**倾向得分匹配 (Propensity Score Matching, PSM)**，为每个处理组关键词在海量未调整的关键词中找到特征最相似的“双胞胎”作为对照组，确保了比较的公平性。
- **验证结果**: 我们的验证脚本覆盖了正效应、零效应和负效应三种场景，证明了DID模块能够准确地计算出真实的因果效应。

## 4. P2: 高级优化层 (Advanced Optimizations)

P2层引入了更前沿的算法，旨在解决更复杂的长周期优化和组合优化问题。

### 4.1. 离线强化学习 (`offlineRLService.ts`)

为了让系统能够从海量历史数据中学习复杂的、多步决策的出价策略，我们实现了**CQL (Conservative Q-Learning)**，一种先进的离线强化学习算法。

- **优势**: 与需要在线“试错”的传统RL不同，Offline RL可以直接从`rl_training_logs`中记录的历史数据进行学习，更安全、更高效。
- **保守Q学习**: CQL的核心思想是在标准Q-Learning的基础上增加一个正则化项，惩罚在历史数据中未出现过的“状态-动作”对的Q值。这使得学习到的策略倾向于执行在历史数据中被证明是安全有效的动作，避免了在真实环境中做出鲁莽的、未经验证的决策。
- **实现**: 我们将状态定义为18维向量（17维上下文 + 1维归一化出价），动作为7个离散化的出价调整幅度。Q函数使用简单的线性模型近似。训练过程通过批量梯度下降完成。

### 4.2. 预算组合优化 (`budgetPortfolioOptimizer.ts`)

在账户层面，如何将有限的总预算分配给多个广告活动（Campaigns），以实现整体利润最大化，是一个经典的组合优化问题。我们通过**基于边际效用的预算分配算法**来解决这个问题。

- **核心原理**: 经济学中的“边际效用等价”原则指出，在最优状态下，投入到每个选项的最后一美元所带来的边际回报应该是相等的。
- **实现**: 
  1. 我们首先为每个Campaign拟合一个“预算-利润”曲线（使用简化的指数函数）。
  2. 然后计算每个曲线的导数，即**边际利润函数** `d(Profit)/d(Budget)`。
  3. 通过二分搜索，我们寻找一个全局的“边际利润阈值 `λ`”，使得所有Campaign在该阈值下的预算之和恰好等于总预算。
- **结果**: 该算法能够智能地将预算从低效率的Campaign转移到高效率的Campaign，从而在不增加总预算的情况下提升整体利润。

### 4.3. 关键词图谱与LLM扩展 (`keywordGraphService.ts`)

该模块利用**大型语言模型 (LLM)** 和图数据库思想，从搜索词报告 (`search_terms`) 中自动发现新的关键词机会和否定关键词机会。

- **机会发现**: 通过分析高点击、高转化的搜索词，并使用LLM进行语义泛化，系统可以推荐新的、有潜力的关键词。
- **否定关键词**: 通过分析高点击、低转化、高花费的无效搜索词，系统可以推荐需要被否定的关键词，从而减少广告浪费。

### 4.4. 元学习策略选择器 (`metaLearningSelector.ts`)

面对如此多的算法（规则、UCB、LinUCB、Sigmoid、CQL），在特定场景下应该使用哪一个？元学习选择器就是为了解决这个问题而设计的“算法的算法”。

- **核心算法**: 我们实现了基于**汤普森采样 (Thompson Sampling)** 的策略选择器。
- **工作原理**:
  1. 为每个可用算法维护一个Beta分布，代表该算法历史表现的“成功”与“失败”次数。
  2. 在每次决策时，从每个算法的Beta分布中采样一个随机数。
  3. 选择采样值最高的算法来执行本次出价。
- **优势**: 汤普森采样天然地平衡了探索（给表现不佳但有潜力的算法更多机会）和利用（更多地使用历史表现最好的算法），能够根据不同关键词的特性和数据量，自动适配到最优的算法。

## 5. 集成与验证

所有独立的算法模块最终都需要被集成到一个统一的流程中，并经过严格验证，以确保其在商业环境中的稳定性和可靠性。

### 5.1. 下一代出价编排器 (`nextGenBidOrchestrator.ts`)

该模块是整个新算法体系的总指挥。它负责编排从特征提取到最终出价的完整决策流程：

1. **流量分配**: 根据确定性哈希算法，决定当前关键词是否使用下一代算法（支持A/B测试）。
2. **元学习选择**: 调用`metaLearningSelector`选择本次决策要使用的核心算法。
3. **算法执行**: 执行被选中的算法（如LinUCB, CQL, Sigmoid等），得到推荐出价。
4. **安全校验**: 对推荐出价进行严格的安全校验，包括绝对范围限制（$0.02-$10）和单次变化幅度限制（±30%）。
5. **RL数据记录**: 调用`rlDataRecorder`记录本次决策的State-Action，用于未来的离线学习。

此外，编排器还负责调度所有后台的定时维护任务，如特征缓存、模型训练、Reward回填等。
