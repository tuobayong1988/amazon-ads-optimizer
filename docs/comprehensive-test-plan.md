# 综合测试计划

## 1. 概述

本测试计划旨在全面验证Amazon广告优化系统新版本的**功能完整性**、**性能稳定性**和**向后兼容性**,确保在Staging和生产环境部署前达到质量标准。

**测试范围:**
- **功能测试:** 所有新功能和核心功能
- **性能测试:** API响应时间、数据库查询、服务器资源使用
- **回归测试:** 现有功能未受影响
- **安全测试:** 权限控制、数据隔离

---

## 2. 测试资源

- **测试环境:** 独立的测试服务器和数据库
- **测试账户:** 至少3个不同规模的Amazon Ads测试账户
- **测试工具:** Vitest, Playwright, Apache Bench, MySQL Slow Query Log

---

## 3. 功能测试 (Test Case)

### 3.1. 组织管理 (多租户)

| 测试用例 | 步骤 | 预期结果 |
| :--- | :--- | :--- |
| **TC-001: 邀请新成员** | 1. 登录为组织所有者<br>2. 进入设置→组织管理<br>3. 输入邮箱地址,选择"成员"角色<br>4. 点击"发送邀请" | 1. 提示"邀请已发送"<br>2. 成员列表中出现新成员,状态为"待定"<br>3. (邮件服务集成后)新成员收到邀请邮件 |
| **TC-002: 接受邀请** | 1. 新成员点击邮件中的链接<br>2. 注册并登录 | 1. 成员状态变为"正常"<br>2. 新成员可以访问组织数据 |
| **TC-003: 移除成员** | 1. 登录为组织所有者<br>2. 点击成员旁的"移除"按钮 | 1. 成员从列表中消失<br>2. 被移除的成员无法再访问组织 |
| **TC-004: 角色权限** | 1. 登录为"成员"角色<br>2. 尝试邀请或移除其他成员 | 1. "邀请成员"按钮不可见或禁用<br>2. "移除"按钮不可见或禁用 |
| **TC-005: 数据隔离** | 1. 创建两个独立的组织A和B<br>2. 在组织A中创建广告活动<br>3. 登录为组织B的成员 | 1. 无法看到组织A的广告活动 |

## 4. 性能测试

| 测试场景 | 工具 | 步骤 | 性能指标 |
| :--- | :--- | :--- | :--- |
| **API并发** | Apache Bench | `ab -n 1000 -c 20 http://test-url/api/campaigns` | P95 < 500ms, 错误率 < 0.1% |
| **数据库查询** | Slow Log | 启用慢查询日志,执行各种操作 | 无超过0.5秒的查询 |
| **前端渲染** | Lighthouse | 在Chrome DevTools中运行Lighthouse | Performance > 80, LCP < 2.5s |
| **内存泄漏** | `top`/`htop` | 持续运行应用24小时,观察内存使用 | 内存使用应保持稳定,无持续增长 |

## 5. 回归测试

```bash

# 确保测试覆盖率不低于80%
pnpm test:coverage
```

## 6. 安全测试

| 测试场景 | 步骤 | 预期结果 |
| :--- | :--- | :--- |
| **越权访问** | 1. 登录为组织A的成员<br>2. 尝试通过API直接访问组织B的数据(如`/api/campaigns?orgId=B`) | 1. API返回403 Forbidden或空数据 |
